Bluetooth often surfaces the SPP profile under two names — the printer's friendly name and its service alias. Either one will work. The system entries ("Peripheral", "Standard Serial") are OS-level shims and won't respond. Wrong Bluetooth endpoint

If you haven't connected yet

        In the picker, pick the entry labelled P780BT or JL_SPP.
        Skip anything labelled Peripheral Bluetooth or Standard Serial over Bluetooth.
      

      

        
On macOS after a disconnect

        This is a known Chromium bug on macOS — tracked upstream at
        issues.chromium.org/345369596.
        Chromium talks to IOBluetoothRFCOMMChannel directly (the same
        API native macOS apps use, which is why those reconnect fine), but
        its Web Serial wrapper doesn't release the channel cleanly on
        port.close(). A stale IOKit reference hangs on, so the next
        port.open() gets a port that looks alive but routes no data.
        Nothing we can do from the browser clears it. Pick whichever of
        these is least annoying for you:
        
    
          
  • Fastest (if you have blueutil): in Terminal,
            blueutil --disconnect <mac> && blueutil --connect <mac>
            — forces bluetoothd to rebuild the channel, no sudo.
    • 
          
  • Reliable, no extra tools:
            System Settings → Bluetooth →
            un-pair the printer → pair it again.
    • 
          
  • Or fully quit Chrome (⌘+Q) and reopen — Chrome
            dropping its file descriptors lets IOKit release the stale
            channel reference.
    • 
          
  • Nuclear (needs sudo, every BT peripheral momentarily
            disconnects): sudo pkill bluetoothd
    •
